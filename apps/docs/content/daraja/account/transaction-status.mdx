**Endpoint**

```
https://sandbox.safaricom.co.ke/mpesa/transactionstatus/v1/query
```

## Overview

To check a transaction's status, you need either its M-PESA receipt number (`TransactionID`) or the `OriginalConversationID` returned when it was first submitted. Safaricom documents this as usable against C2B, B2B, B2C, Reversal, and IMT transactions.

## How it works

The organization sends the query to Daraja, which authenticates it and forwards it to M-PESA. M-PESA checks the transaction's status and responds to Daraja, which posts the result back to the organization's `ResultURL`.

## Prerequisites

- Daraja account and sandbox app.

## Request

```json
{
  "Initiator": "testapiuser",
  "SecurityCredential": "ClONZiMYBpc65lmpJ7nvnrDmUe0WvHvA5QbOsPjEo92B6IGFwDdvdeJIFL0kgwsEKWu6SQKG4ZZUxjC",
  "CommandID": "TransactionStatusQuery",
  "TransactionID": "NEF61H8J60",
  "OriginalConversationID": "7071-4170-a0e5-8345632bad442144258",
  "PartyA": "600782",
  "IdentifierType": "4",
  "ResultURL": "http://myservice:8080/transactionstatus/result",
  "QueueTimeOutURL": "http://myservice:8080/timeout",
  "Remarks": "OK",
  "Occasion": "OK"
}
```

| Field | Description | Sample value |
|---|---|---|
| `CommandID` | Always `TransactionStatusQuery`. | `TransactionStatusQuery` |
| `PartyA` | Organization short code or MSISDN that received the transaction. | 6 to 9 digit short code or 12-digit MSISDN |
| `IdentifierType` | `4` for an organization short code. | `4` |
| `Initiator` | Username authenticating the request. | Username |
| `SecurityCredential` | Encrypted initiator credential. | (encrypted string) |
| `TransactionID` | The M-PESA receipt number of the transaction being checked. | `LXXXXXX1234` |
| `OriginalConversationID` | The Originator Conversation ID of the transaction being checked. | `7071-4170-a0e5-8345632bad442144258` |
| `ResultURL` / `QueueTimeOutURL` | Result and timeout callback URLs. | `https://domain:port/path` |
| `Remarks` | Up to 100 characters. | Free text |
| `Occasion` | Optional, up to 100 characters. | Free text |

<Callout type="info">
Note the spelling here: this API's optional field is `Occasion` (single "s"), unlike the `Occassion` (double "s") documented on the B2C/B2B family. Both are reproduced as Safaricom spells them on their respective pages.
</Callout>

<Callout type="warn" title="Defect in the source material">
Safaricom's own sample lists the `DebitPartyName` key twice, with two different values, in the same `ResultParameter` array, and includes a `TransactionReason` entry with no `Value` at all. Both are reproduced exactly as documented.

| Field | Description |
|---|---|
| `ConversationID` | Unique identifier generated by M-PESA for the request. |
| `OriginatorConversationID` | Identifier of the original request message. |
| `ResultCode` | `0` for success. |
| `ResultDesc` | Description of the result code, up to 1024 characters per Safaricom's documentation. |
| `ResultType` | `0` completed, `1` waiting for further messages. |
| `TransactionID` | M-PESA's own transaction identifier, present only for transaction requests. |
| `ResultParameters.ResultParameter` | Key-value detail: debit/credit party names, account type, timestamps, amount, charges, receipt number, and transaction status. |

## Transaction status values

Safaricom documents three broad states a transaction can be in:

- **Initiated**, pending revalidation.
- **Authorized / Pending Authorized**, waiting on the credit party's validation response.
- **Final status**: Cancelled, Declined, Completed, or Expired.

## Testing

**Step 1**: Get your app's Consumer Key and Consumer Secret from the portal.
**Step 2**: Generate an access token from the sandbox or production OAuth endpoint.
**Step 3**: Submit the query with either `TransactionID` or `OriginalConversationID`, plus `PartyA`.

## Go Live

Requires the **Transaction Status Query ORG API** role on the initiator; see [Organization Portal & Go Live](/daraja/organization-portal) for creating and configuring that operator.
