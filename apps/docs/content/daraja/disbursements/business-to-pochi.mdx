A variant of the B2C API for paying into **Pochi la Biashara**, the informal-business wallet product Safaricom markets to micro and small merchants.

**Endpoint**

```
https://sandbox.safaricom.co.ke/mpesa/b2pochi/v1/paymentrequest
```

## Overview

Mechanically this mirrors [B2C](/daraja/b2c) closely enough that Safaricom's own documentation reuses B2C wording in places (see the callout below); the distinguishing points are the endpoint and the `CommandID`.

## Prerequisites

Same as [B2C](/daraja/b2c) (Daraja account, sandbox app, `InitiatorName`/`InitiatorPassword`, encrypted `SecurityCredential`, live B2C shortcode with operators created), plus one addition specific to this API:

- The receiving party must actually have a Pochi la Biashara / Micro SME business wallet. Safaricom doesn't document a way to check this ahead of a payment attempt.

## Request

```json
{
  "OriginatorConversationID": "600997_Test_32et3241ed8yu",
  "InitiatorName": "testapi",
  "SecurityCredential": "RC6E9WDxXR4b9X2c6z3gp0oC5Th ==",
  "CommandID": "BusinessPayToPochi",
  "Amount": "10",
  "PartyA": "600992",
  "PartyB": "254705912645",
  "Remarks": "remarked",
  "QueueTimeOutURL": "https://mydomain.com/path",
  "ResultURL": "https://mydomain.com/path",
  "Occassion": "ChristmasPay"
}
```

| Field | Description | Sample value |
|---|---|---|
| `OriginatorConversationID` | Your own unique ID per request. | `600997_Test_32et3241ed8yu` |
| `InitiatorName` | API operator username. | `johndoe` |
| `SecurityCredential` | Encrypted initiator password. | (encrypted string) |
| `CommandID` | `BusinessPayToPochi` for this API. | `BusinessPayToPochi` |
| `PartyA` | Your B2C short code. | `600997` |
| `PartyB` | Recipient's MSISDN. | `254705912645` |
| `Occassion` (sic) | Optional, 1 to 100 characters. | Free text |

<Callout type="warn" title="Defect in the source material">
The `CommandID` field description in Safaricom's own documentation for this API lists `BusinessPayToPochi` alongside `SalaryPayment`, `BusinessPayment`, and `PromotionPayment` as if they were interchangeable options, which is B2C's set of command IDs, not B2Pochi's. Only `BusinessPayToPochi` is documented as valid for this specific endpoint. `Occassion` is spelled with a double "s" in the source, kept as-is since it's the literal field name.
</Callout>

## Response

```json
{
  "ConversationID": "AG_20240706_20106e9209f64bebd05b",
  "OriginatorConversationID": "600997_Test_32et3241ed8yu",
  "ResponseCode": "0",
  "ResponseDescription": "Accept the service request successfully."
}
```

## Callback payload

Structurally identical to the [B2C](/daraja/b2c) callback: `ResultType`, `ResultCode`, `ResultDesc`, `TransactionID`, and a `ResultParameters.ResultParameter` array carrying `TransactionAmount`, `TransactionReceipt`, `ReceiverPartyPublicName`, `TransactionCompletedDateTime`, and the B2C account balance fields (`B2CUtilityAccountAvailableFunds`, `B2CWorkingAccountAvailableFunds`, `B2CRecipientIsRegisteredCustomer`, `B2CChargesPaidAccountAvailableFunds`).

## Testing and Go Live

Same path as [B2C](/daraja/b2c): Daraja Simulator with the B2Pochi product attached, or Postman against the sandbox endpoint above. Going live requires the same B2C shortcode/one-account setup described in [Organization Portal & Go Live](/daraja/organization-portal).

## FAQs

<Accordions>
<Accordion title="Can I have both B2Pochi and C2B on the same app?">
Yes, if both are enabled for your short code on M-PESA.
</Accordion>
<Accordion title="Can I reverse a B2Pochi transaction?">
No. Safaricom documents this as a manual process on the M-PESA portal, same as B2C.
</Accordion>
<Accordion title="Do I need a passkey?">
No, passkeys are specific to M-Pesa Express/STK Push.
</Accordion>
<Accordion title="Is there an API to move funds from a Pay Bill into a B2C short code first?">
Yes, see [B2C Account Top Up](/daraja/b2c-account-top-up).
</Accordion>
</Accordions>
