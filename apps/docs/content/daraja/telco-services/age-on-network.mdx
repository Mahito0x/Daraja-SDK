**Endpoint**

```
https://sandbox.safaricom.co.ke/registration/lookup/v1/checkATI
```

## Overview

Returns the original registration date of a SIM card, i.e. how long a given Safaricom number has existed on the network. Safaricom lists this as useful for KYC checks, onboarding validation, compliance monitoring, fraud prevention, and analytics, and notes it specifically as able to confirm whether a SIM's age on network is under six months.

<Callout type="warn" title="Defect in the source material">
Safaricom's own "Good to Know" section for this API states it is **asynchronous**, but the request/response pair documented for it returns the registration date directly in the HTTP response, with no callback URL field anywhere in the request body and no callback payload documented. As published, this API reads as synchronous in practice; both statements come from Safaricom's own page.
</Callout>

## How it works

1. The organization sends the customer's phone number to Daraja.
2. Daraja authenticates the request and forwards it to Safaricom's CRM system.
3. The CRM system returns the SIM's registration date.

## Request

```json
{ "customerNumber": "254722000000" }
```

| Field | Description | Sample value |
|---|---|---|
| `customerNumber` | MSISDN to check, 12-digit `254XXXXXXXXX` format. | `2547XXXXXXXX` |

## Response

```json
{
  "requestRefID": "93b1-4738-94b2-52a821a080656023",
  "responseCode": "200",
  "responseDesc": "Success",
  "msisdnRegistrationDate": "01-01-1900",
  "customerNumber": "254722000000"
}
```

| Field | Description | Sample value |
|---|---|---|
| `requestRefID` | Unique ID per request. | `4277-415525-1` |
| `responseCode` | `200` success; any other value is an error. | `200` |
| `responseDesc` | Status message. | `Success` |
| `msisdnRegistrationDate` | The SIM's registration date, or a message stating registration is more than a year old, per Safaricom's field description. | `2019-01-12` |
| `customerNumber` | Echoed back. | `254722000000` |

<Callout type="info">
The sample `msisdnRegistrationDate` value Safaricom shows, `01-01-1900`, is a date well before mobile telephony existed in Kenya, let alone Safaricom's own 2000 launch. It reads as a placeholder or null-date convention rather than a genuine sandbox result, though Safaricom's documentation doesn't say so explicitly.
</Callout>

## Testing

**Daraja Simulator**: create a test app with the Age on Network product attached.

**Postman**: generate an access token from the sandbox OAuth endpoint using your Consumer Key and Secret, then call the endpoint above.

<Callout type="warn" title="Defect in the source material">
Safaricom's own Postman instructions list identical URLs for both Sandbox and Production when generating an access token, both pointing at `sandbox.safaricom.co.ke`. The production OAuth host used consistently elsewhere in Daraja's documentation is `api.safaricom.co.ke`; this appears to be a copy-paste error on Safaricom's part, reproduced here as published rather than silently corrected.
</Callout>
