The SDK is a server-side TypeScript client for Safaricom's Daraja API. It uses
standard `fetch`, `AbortController`, timers, Base64 encoding, and
`Intl.DateTimeFormat` for the East Africa timestamp required by STK Push.
There is one package and one client shape: create it once, then call it from
your framework's server boundary.

<Callout title="Keep credentials on the server" type="error">
  Never import the SDK into a browser component or expose `consumerKey`,
  `consumerSecret`, passkeys, or security credentials to the client. Use a route
  handler, loader, action, server endpoint, or backend service instead.
</Callout>

## Runtime fit

The package declares Node.js `>=20.19.0` and is tested as a Node-first SDK.
Its HTTP layer uses Web APIs, so it can also fit other server runtimes that
provide compatible `fetch`, `AbortController`, Base64, timers, and
`Intl.DateTimeFormat` support.

<Callout title="Edge runtime note" type="warn">
  Edge deployments are not the primary tested target. The SDK uses `btoa` when
  available and falls back to `Buffer` for Base64 encoding, so verify the target
  platform's globals before deploying to an edge isolate. In Next.js, use the
  default Node.js runtime unless you have verified the specific edge deployment
  yourself.
</Callout>

## Shared setup

Construct the client at module scope so its in-memory OAuth token cache can be
reused between requests.

<Tabs items={["Node.js / Express", "Next.js"]}>
  <Tab value="Node.js / Express">

```ts title="src/daraja.ts"
import { Daraja } from "@lumierelabs/daraja";

export const daraja = new Daraja({
  environment:
    process.env.DARAJA_ENVIRONMENT === "production" ? "production" : "sandbox",
  consumerKey: process.env.DARAJA_CONSUMER_KEY!,
  consumerSecret: process.env.DARAJA_CONSUMER_SECRET!,
  passkey: process.env.DARAJA_PASSKEY!,
  shortcode: process.env.DARAJA_SHORTCODE!,
  callbackUrl: process.env.DARAJA_CALLBACK_URL!,
});
```

  </Tab>
  <Tab value="Next.js">

```ts title="lib/daraja.ts"
import { Daraja } from "@lumierelabs/daraja";

export const daraja = new Daraja({
  environment:
    process.env.DARAJA_ENVIRONMENT === "production" ? "production" : "sandbox",
  consumerKey: process.env.DARAJA_CONSUMER_KEY!,
  consumerSecret: process.env.DARAJA_CONSUMER_SECRET!,
  passkey: process.env.DARAJA_PASSKEY!,
  shortcode: process.env.DARAJA_SHORTCODE!,
  callbackUrl: process.env.DARAJA_CALLBACK_URL!,
});
```

  </Tab>
</Tabs>

Call methods such as `daraja.stkPush()`, `daraja.stkPushQuery()`,
`daraja.c2b.registerUrl()`, or `daraja.b2cTopUp.topUp()` from the server
boundary. Catch `DarajaError` to return a stable error code and HTTP status to
your application.

## Scaffold with the CLI

`create-daraja` currently generates complete Next.js and Express projects,
including only the selected service routes.

<Steps>
  <Step>

```bash title="Terminal"
npx create-daraja@latest
```

  </Step>
  <Step>

Choose Next.js or Express, select sandbox or production, then select STK Push,
STK query, C2B, or B2C Account Top Up.

  </Step>
  <Step>

Copy `.env.example` to `.env`, add your credentials, install dependencies, and
start the generated dev server. The CLI never creates a real `.env` file.

  </Step>
</Steps>

<Callout title="Adding another framework" type="info">
  The SDK has no Express, Next.js, Astro, or Remix dependency. A new adapter
  only needs to construct the client once and call its methods from the
  framework's server boundary.
</Callout>
