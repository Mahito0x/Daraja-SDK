Every endpoint that accepts a webhook URL `mpesaExpress.push()`'s `callBackURL`, `c2b.registerUrl()`'s `confirmationUrl`/`validationUrl`, and `b2cTopUp.topUp()`'s `queueTimeOutURL`/`resultURL` runs the same `validateCallbackUrl()` check before the request is sent.

## What gets checked, in order

1. **Presence** must be a non-empty string
2. **Valid URL** must parse with the `URL` constructor and use `http:` or `https:`
3. **HTTPS in production** if `environment: 'production'`, `http://` URLs are rejected outright
4. **No banned keywords** the hostname+path can't contain `mpesa`, `safaricom`, `exec`, or `sql` (case-insensitive). These are local SDK validation rules.
5. **No configured tunneling hosts** `ngrok.io`, `ngrok-free.app`, `ngrok.app`, `mockbin.org`, `requestbin.com`, and `requestbin.net` (and their subdomains) are rejected by the SDK.

```ts
// Throws INVALID_CALLBACK_URL: "callBackURL contains a disallowed keyword
// (\"mpesa\")."
await daraja.stkPush({
  // ...
  callBackURL: "https://example.com/mpesa-callback",
});
```

<Callout type="warn" title="Local development">
  The SDK rejects the tunnel hosts listed above. Use a public domain or a tunnel
  host that is not on the SDK's blocklist, then verify the callback behavior in
  the Daraja environment you are targeting.
</Callout>

## Which fields this applies to

| Endpoint              | Fields validated                   |
| --------------------- | ---------------------------------- |
| `mpesaExpress.push()` | `callBackURL`                      |
| `c2b.registerUrl()`   | `confirmationUrl`, `validationUrl` |
| `b2cTopUp.topUp()`    | `queueTimeOutURL`, `resultURL`     |

There is currently no config flag to relax these checks. Rename a route or use a different hostname when a legitimate URL matches a blocked value.
